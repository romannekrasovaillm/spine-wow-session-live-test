# CI-шаблон ДКА

Эти файлы — **механизм контроля**: пишутся и проверяются людьми один раз, лежат в репозитории
ДКА `dka-ci`. Агент их не генерирует и не правит; он генерирует только данные для механизма
(правила, требования, примеры selftest).

| Файл | Назначение |
|---|---|
| `dka-gate.sh` | Гейт: эффективный файл ДКА → проверка корпоративного слоя с исполнением контрактов ДКА; ослабление собственных правил продукта |
| `build_effective.py` | Правила только из слоя ДКА, исключения только из реестра ДКА, срок не больше 180 дней |
| `Jenkinsfile` | Джоба ДКА: берёт скрипт из checkout ДКА, публикует JUnit и артефакты |

Структура репозитория ДКА:

```
dka-ci/
  ci/                      эти файлы
  corp/CONSTRAINTS.corp.yaml
  exceptions/<продукт>.yaml
  baselines/<продукт>.json
  contracts/               контрактные тесты ДКА (поведенческие проверки)
```

Настройки Bitbucket: права на ветки ДКА — только владельцы; обязательная сборка со статусом
джобы ДКА перед слиянием в продуктах; обязательные ревьюеры ДКА на `dka-ci`.

Проверка шаблона перед использованием: `session.py ci-redteam` — набор атак продукта на гейт.
