# Контрактные тесты ДКА

Поведенческие проверки смысловых требований, которые регулярными выражениями не проверяются.
Spine Core запускает их правилом `command_succeeds` и выносит повторяемый вердикт; находит
нарушение сам тест.

| Контракт | Требование | Что проверяет |
|---|---|---|
| `idempotency/` | §4.1 Идемпотентность авторизации | Повторный вызов с тем же ключом возвращает исход первого и не списывает повторно; разные ключи — разные операции |

Правило в корпоративном слое:

```yaml
- name: idempotency_contract
  type: command_succeeds
  command: 'bash "$DKA_HOME/contracts/idempotency/run_contract.sh"'
  timeout_secs: 900
  std_ref: "§4.1 Идемпотентность"
  severity: block
```

Условия:

- **Контракт API — часть стандарта.** Тест вызывает `Processor::default()`, `Payment::default()`,
  `authorize(key, &payment)` и сравнивает `Receipt.id`. Для реальных сервисов контракт пишется
  под их интерфейс (или стандарт требует тестового фасада).
- **Команда берётся только из слоя ДКА.** Эффективный файл собирается из реестра ДКА, поэтому
  гейт исполняет корпоративные команды, а продуктовые — нет (`--no-exec` для правил продукта).
- **Тест компилирует и запускает код продукта** — только в изолированном агенте CI.
- Нужен `cargo`; зависимости скачиваются один раз в общий кэш `DKA_CARGO_TARGET`.
