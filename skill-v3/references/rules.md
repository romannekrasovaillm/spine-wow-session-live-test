# Правила Spine Core: шпаргалка для генерации CONSTRAINTS.corp.yaml

Сверено с `docs/control.md` и `docs/corp-spine.md` Spine Core 0.3.8. При другой версии
сверяйтесь с документацией установленной версии: схема может меняться.

## Каркас файла корпоративного слоя

```yaml
version: "2026.1"          # обязательно для корпоративного слоя: по нему продукты пинуются
constraints:
  - id: C-DKA-001          # необязательно; связь с трассировкой
    name: tech_radar_hold  # уникальное имя; по нему работают override и отчёты
    type: deny_dependency
    severity: warn         # warn на старте; block/error — только после selftest
    std_ref: "Техрадар, раздел HOLD"        # ссылка на пункт стандарта (поле скилла)
    rationale: "[Техрадар ДКА, HOLD] ..."   # видно в находке — начинайте со ссылки на пункт
    fix_hint: "заменить на ..."            # необязательно: как исправить
    owner: "@dka-integration"              # необязательно: владелец правила
```

`std_ref` — поле этого скилла: Spine его допускает и игнорирует, а `session.py` строит по нему
прослеживаемость «находка → пункт стандарта». Дублируйте ссылку в начале `rationale`:
именно `rationale` попадает в находку Spine.

## Поля скилла (Spine их допускает и игнорирует, использует session.py)

| Поле | Назначение |
|---|---|
| `std_ref` | Пункт стандарта; обязателен для всех проверяемых правил (`lint-rules`) |
| `applies_to: [тег]` | Область действия: правило проверяет только репозитории с этими тегами из `session.yaml` |
| `closed_by: [имя]` | Хрупкое правило закрыто парой: `block` разрешён, если все правила из списка «надёжно» |

Правила `must_contain` и `each_file_must_contain` не запускаются для репозитория, где по `glob`
нет ни одного файла: Spine на пустом наборе даёт находку, которая не является нарушением.

## Типы правил

| type | Что проверяет | Обязательные поля | Надёжность |
|---|---|---|---|
| `deny_dependency` | Пакет из списка есть в манифесте (Cargo.toml, pom.xml, requirements.txt) | `deny`, желательно `reference` | Средняя–высокая: ловит прямые имена; **переименование зависимости в Cargo (`lp = { package = "left-pad" }`) обходит**; других экосистем пока нет |
| `dependency_direction` | Импорты файлов не нарушают `forbid`/`allow` префиксов модулей (Rust, Python, Java/Kotlin, TS/JS) | `glob`, ровно одно из `forbid`/`allow` | Средняя: текстовый разбор, не AST |
| `context_boundary` | Импорты не пересекают границы контекстов из модели | см. docs/control.md | Средняя |
| `archunit` | Те же java-правила настоящим ArchUnit по байткоду | см. docs/archunit.md | Высокая; нужна JVM и собранные классы |
| `must_not_contain` | Паттерн не встречается в файлах по `glob` | `glob`, `pattern` | Низкая–средняя: текст |
| `must_contain` | Паттерн есть хотя бы в одном файле | `glob`, `pattern` | **Низкая: обходится упоминанием в комментарии** |
| `each_file_must_contain` | Паттерн есть в каждом файле по `glob` | `glob`, `pattern` | Низкая |
| `file_exists` | Файл или каталог существует | `path` | Средняя (проверяет наличие, не содержание) |
| `dir_must_have_file` | В каждом каталоге по `glob` есть файл `path` | `glob`, `path` | Средняя |
| `max_age` | Файл существует и не старше `max_age_days` | `path`, `max_age_days` | Средняя |
| `command_succeeds` | Команда завершается кодом 0 | `command`, `timeout_secs` | Высокая для поведенческих тестов; **не исполняется в `--no-exec`** |
| `unverifiable: true` | Не исполняется, видно в отчёте как долг ручного контроля | `owner` | — |

## Синтаксис

- **glob:** `**` — любая глубина, `*` — внутри сегмента, `?` — один символ. Можно список строк.
  **Фигурные скобки `{a,b}` не поддерживаются** — используйте список:
  `glob: ["**/*.java", "**/*.kt"]`.
- **pattern:** регулярное выражение по всему файлу. `^`/`$` — начало и конец файла;
  для построчной семантики добавьте `(?m)`.
- **severity:** `warn` — только в отчёт; `block`/`error` (а также critical/high) — ломает гейт.
- Правило может сработать на собственном описании (слово из запрета в комментарии) —
  учитывайте в `pattern` и `exclude_glob`.

Пример усиления: запрет чисел с плавающей точкой для денег шаблоном `\bf64\b` обходится через `f32`;
шаблон `\bf(32|64)\b` этот обход ловит. Такие находки даёт `session.py selftest`.

## Что генерировать в первую очередь

1. `deny_dependency` для техрадара.
2. `dependency_direction` для границ доменов и слоёв (для JVM позже — `archunit`).
3. `must_not_contain` для секретов, запрещённых конструкций, номеров карт.
4. Требования, которые проверяются только наличием слов (`must_contain`), — оставлять в `warn`
   и показывать как пример хрупкого правила; настоящая проверка — поведенческий тест
   через `command_succeeds` (в пилоте, вне `--no-exec`).
5. Всё, что нельзя проверить, — `unverifiable: true` с `owner`: честный долг ручного контроля.

## Пример набора для интеграционного стандарта

```yaml
version: "2026.1"
constraints:
  - id: C-INT-001
    name: tech_radar_hold
    type: deny_dependency
    deny: [log4j-core, commons-collections]
    reference: "Техрадар ДКА, HOLD"
    std_ref: "Техрадар, HOLD"
    rationale: "[Техрадар, HOLD] библиотека запрещена"
    severity: warn
  - id: C-INT-002
    name: no_cross_domain_imports
    type: dependency_direction
    glob: ["src/**/*.java", "src/**/*.kt"]
    forbid: ["ru/bank/crm/internal", "ru/bank/cards/internal"]
    std_ref: "Стандарт интеграции §3.1"
    rationale: "[Стандарт интеграции §3.1] доступ к другому домену — только через его API"
    severity: warn
  - id: C-INT-003
    name: no_secret_literals
    type: must_not_contain
    glob: ["**/*.java", "**/*.kt", "**/*.py", "**/*.yaml", "**/*.properties"]
    pattern: "(?i)(password|secret|token)\\s*[=:]\\s*['\"][^'\"]{8,}"
    std_ref: "Стандарт безопасности §5.4"
    rationale: "[Стандарт безопасности §5.4] секреты только из хранилища секретов"
    severity: warn
  - name: observability_standard
    unverifiable: true
    owner: "@dka-observability"
    std_ref: "Стандарт наблюдаемости §2"
```
