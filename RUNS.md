# Два прогона: длинные промпты против коротких фраз

Первый прогон получился с методической оговоркой: в TUI вставлялись **не слова архитектора,
а промпт-шаблоны P1/P2 из самого навыка** (`references/prompts.md`) — с классами проверяемости,
именами файлов и требованием `std_ref`. Живой человек так не пишет. Такой прогон доказывал,
что навык исполняется, но почти не проверял, что агент **сам** дойдёт до его процедур.

Второй прогон закрывает именно это: та же машина, тот же навык и стандарт, но **четыре короткие
реплики живой речи** и намеренно пустая рабочая папка.

## Реплики второго прогона (дословно)

```
1. Мой стандарт лежит в context/standard/, репозитории перечислены в session.yaml.
   Покажи, что у меня нарушается.

2. Хочу, чтобы это проверялось в CI, а не только сегодня.
   И проверь, что правилам вообще можно доверять.

3. Стандарт будет меняться. Как выпустить новую версию и увидеть, кто её ещё не применил?
   И что команда сможет обойти?

4. Собери раздатку к встрече и честно скажи, что ещё не готово.
```

## Промпты первого прогона (для сравнения, фрагмент)

```
Действуй по навыку spine-wow-session, этап подготовки, шаг 1: разбери стандарт на
атомарные требования и заполни work/requirements.md — ID, формулировка, пункт стандарта,
класс проверяемости A/B/C, способ проверки, будущее имя правила. …
```

Восемь таких промптов подряд — это фактически передача агенту чек-листа навыка; агент
в этом режиме работает диспетчером шагов.

## Сравнение

| Параметр | Прогон 1: промпты-шаблоны | Прогон 2: короткие фразы |
|---|---|---|
| Реплик архитектора | 8 длинных (по 1–3 абзаца) | **4 короткие** (1–2 предложения) |
| Кто выбирал процедуру | подсказано в промпте | **агент сам** по `SKILL.md` |
| Состояние `work/` на старте | подложены правила и примеры | чистые шаблоны |
| Отчётов механики | 8 | **13** |
| Вызовов `session.py` | 12 | **20** |
| Команд агента | 31 | **57** |
| `write_file` / `edit` | 8 / 3 | **46 / 15** |
| Остановок на решение человека | 1 | 3 |
| Контур CI (Jenkinsfile, gate.sh) | нет | **есть** |
| `pilot-canvas.md` | остался шаблоном | **заполнен** |
| Самоисправление вердикта правила | нет | **есть** (сменил «надёжно» на «хрупко») |
| Список «не проверено вовсе» | 7 пунктов незакрытого | **13 пунктов готовности** |

## Что из этого следует

1. **Навык активируется с обычной речи.** Первая же фраза «покажи, что у меня нарушается»
   развернулась в полный цикл подготовки: разбор стандарта → требования с классами → правила
   со ссылками на пункты → `preflight` → `check` с находками `файл:строка + §`.
2. **Длинные промпты были артефактом тестирования, а не требованием навыка.** Они полезны как
   детерминированный способ прогнать конкретный шаг, но для демонстрации ценности навыка
   достаточно одной-двух фраз — и результат получается даже богаче.
3. **Меньше подсказок → больше самостоятельности, но и больше разброс.** Второй прогон добавил
   то, чего в первом не было (CI-гейт, план пилота, самоисправление), однако появились и
   лишние файлы, и оговорки от агента. Для встречи с архитектором это скорее плюс: видно,
   где навык требует решения человека.
4. **Граница честности не сдвинулась.** Оба прогона учебные: демо-стандарт, три учебных
   репозитория, настоящий CI не запускался.

# Четвёртый прогон: третья версия навыка

Версия 3 выросла прямо из дефектов, найденных на прогоне 3: заранее написанный вывод дуэли,
два участника вместо трёх, `SyntaxError` на Python 3.9–3.11, неотыгранный блок флота,
статичная шапка `check.md`.

| Дефект прогона 3 (v2) | Прогон 4 (v3) |
|---|---|
| Вывод дуэли написан заранее и противоречил числам | выводы **вычислены из данных**: по категориям, времени, стабильности; проигрыш движка по смыслу назван прямо |
| Участников двое | **четверо**: Spine Core, чистая LLM, LLM + находки Spine Core и расчётная маршрутизация |
| 12 случаев, подсказки в комментариях, 1 прогон LLM | **16 случаев** в пяти категориях; по **3 прогона** каждого набора, вердикт большинства |
| `session.py` падал на Python 3.9–3.11 | прогон целиком на **Python 3.11.8** |
| Блок «версия стандарта и флот» не отыгран | `fleet init/bump/report/repin` пройдены |
| Статичная шапка `check.md` | шапка динамическая |

## Дуэль: числа

| Показатель | Spine Core | Чистая LLM | LLM + Spine Core | Маршрутизация |
|---|---|---|---|---|
| Верно решённых из 16 | **11** | 12–16 | **16** | **16** |
| Пропуски / ложные | 3 / 2 | 0–2 / 0–2 | 0 / 0 | 0 / 0 |
| Стабильность между прогонами | **16 из 16** | **12 из 16** | 16 из 16 | — |
| Время на набор, с | **0.2** | 240 / 53 / 300 | 300 / 180 / 420 | — |

Вывод, который теперь следует из чисел, а не из текста: **формальное и повторяемое — за движком,
смысловое — за моделью, решение опирается на обоих.** Комбинация закрывает 16 из 16.

## Что прогон 4 оставил незакрытым

1. Статичная строка `handout/README.md` («решает движок… повторяемо, без усталости») расходится
   с числами дуэли — агент отказался править механизм и предложил страницу-врезку.
2. `pilot-canvas.md` заполнен только выводимой частью: продукты, люди и критерии успеха —
   решения архитектора.
3. `precision` не сертифицирована (0.21 < 0.9), в `block` — только подтверждённые правила.
4. `reports/duel.md` содержит истину по всем 16 случаям: для повторной дуэли с другой моделью
   его показывать участникам нельзя.

# Третий прогон: вторая версия навыка

Прогон 3 отличается от предыдущих не промптами, а **версией навыка**: взят
[`skill-v2`](skill-v2) — с шаблоном CI-гейта, `ci-redteam`, `lint-rules`, `precision`,
`duel` и `done-check`. Реплик шесть, все короткие, папка на старте чистая.

## Что изменилось в поведении

| Наблюдение | Навык v1 (прогон 2) | Навык v2 (прогон 3) |
|---|---|---|
| Просьба «проверялось в CI» | агент **сгенерировал** гейт (Jenkinsfile, gate.sh) | агент **развернул готовый шаблон** и прогнал `ci-redteam` |
| Защищённость гейта | утверждалась текстом | **измерена**: 7 атак из 7; у схемы «гейт в продукте» — 2 обхода |
| Блокирующие правила | решал агент | решает `lint-rules` + `precision`; одно решение агента отклонено |
| Вакуумные находки | были (пустой `src/**/*.rs`) | нет: области действия `applies_to` + теги |
| Объявление готовности | по тексту ответа | только `done-check` = 0 |
| Дуэль с LLM | нет | **Spine 10/12 за 0.2 с**, LLM 12/12 за 300 с |
| Команд агента / `session.py` | 57 / 20 | 28 / 20 (меньше генерации — больше проверки) |
| Отчётов | 13 | 15 (добавились `ci-redteam`, `duel`, `precision`, `lint-rules`) |

## Что прогон 3 оставил незакрытым

1. `session.py` v2 требует **Python 3.12+** (вложенные кавычки в f-string), а `SKILL.md`
   заявляет 3.9+ — на 3.9–3.11 скрипт падает с `SyntaxError`.
2. Блок «версия стандарта и флот» (`fleet init/bump/report`) не отыгран: агент ушёл
   в ветку CI и дуэли.
3. `precision` не сертифицируется на выборке 1 находка на правило (0.21 < 0.9) —
   блокирующих правил только два.
4. Шапка `reports/check.md` остаётся статичным текстом шаблона и расходится с таблицей ниже.
