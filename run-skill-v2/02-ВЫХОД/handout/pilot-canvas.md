## 4. Что замерить до старта
- время ревью архитектора на MR с архитектурными изменениями;
- нарушения, найденные поздно (после слияния);
- число действующих исключений и их учёт.

Уже видно на сессии: `left-pad` в `cards-product` имеет override `ADR-041` в своём
`CONSTRAINTS.yaml`, но его нет в реестре исключений ДКА — поэтому гейт ДКА сообщает о нарушении.
Это единица долга в учёте исключений, а не ложное срабатывание.

## 5. Успех через 8–10 недель — это…
- гейт блокирует PR пилотных продуктов по эффективному файлу ДКА, а не по продуктовому;
- ни одного блокирующего правила без вердикта selftest «надёжно» и нижней границы точности ≥ 0.9
  на выборке 20–30 находок;
- корпоративный слой версионирован, продукты перепинены осознанным PR (`extends @версия`);
- все исключения — только через реестр ДКА, с существующим ADR и сроком ≤ 180 дней;
- `ci-redteam`: шаблон гейта отбивает все атаки продукта.
