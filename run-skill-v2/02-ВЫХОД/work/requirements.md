# Требования стандарта: Стандарт платёжного ядра v2

Источник: context/standard/payment-core-standard.md (экспорт Confluence). Сгенерировано агентом, проверено архитектором: нет.

Классы проверяемости:
- **A** — проверяется автоматически по коду, зависимостям или конфигурации;
- **B** — частично: нужен тест или анализ структуры кода;
- **C** — только человеком.

| ID | Требование | Пункт стандарта | Класс | Как проверить | Правило |
|---|---|---|---|---|---|
| R-01 | Денежные суммы не хранятся в типах с плавающей точкой | §2.1 | A | запрет типов `f32`/`f64` в исходниках Rust | no_float_for_money |
| R-02 | Ошибки домена описываются типизированно, через thiserror | §3.2 | B | наличие зависимости thiserror в манифесте (структурно); поведение — исчерпывающий match по вариантам ошибки | thiserror_for_errors |
| R-03 | anyhow и `Box<dyn Error>` запрещены | §3.2 | A | запрет зависимости anyhow; запрет `Box<dyn Error>` в коде — **неоднозначно**: вторая половина пункта правилом пока не покрыта (кандидат на warn-правило и пример) | tech_radar_hold (anyhow) |
| R-04 | Авторизация платежа идемпотентна по ключу | §4.1 | B | **неоднозначно**: поведение проверяется тестом (повторный вызов с тем же ключом не повторяет сайд-эффект); поиск по ключевому слову — только прокси | authorize_idempotent |
| R-05 | Библиотеки из зоны HOLD (anyhow, left-pad) не используются | §5.1 | A | запрет прямого подключения зависимости; отдельно — подключение HOLD-пакета под псевдонимом в Cargo | tech_radar_hold, tech_radar_renamed |
| R-06 | Каждый сервис публикует метрики по стандарту наблюдаемости | §6.1 | C | только человеком: наличие и состав метрик | — (unverifiable) |
