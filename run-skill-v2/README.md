# Прогон второй версии навыка (spine-wow-session v2)

Живой прогон **второй версии скилла** в TUI Qwen Code 0.24.4: шесть коротких реплик
архитектора, чистая рабочая папка, проверки — механикой Spine Core (`arch-be 0.3.8`).

Сам скилл лежит в репозитории рядом: [`../skill-v2/`](../skill-v2).

## Что изменилось в v2 и что это дало на прогоне

| Замысел v2 | Как проявилось в живом прогоне |
|---|---|
| **Данные, а не механизм:** CI-гейт — готовый шаблон `assets/ci/`, агент его не пишет | На реплику «хочу, чтобы это проверялось в CI» агент **не стал генерировать гейт**, а развернул шаблон и прогнал `ci-redteam` |
| **Состязательная проверка исполняемая:** `ci-redteam` атакует гейт | Шаблон ДКА отбил **7 атак из 7**; схема «гейт внутри продукта» пропустила 2 (фальшивый ADR и подмена скрипта) |
| **Метаправила:** `lint-rules` проверяет реестр | `lint-rules` **отклонил собственное решение агента** — `block` для `tech_radar_hold` без подтверждённой точности |
| **Области действия:** `applies_to` + `tags` | На `cards-product` (тег `cards`) правила §2.1/§3.2/§4.1 не применяются — вакуумных находок нет, в отчёте строка «не проверялось» |
| **Точность выборкой:** `precision` | Точность **не сертифицирована**: 1 находка на правило даёт нижнюю границу 0.21 < 0.9, поэтому блокирующих правил только два |
| **Разделение ролей:** `done-check` | Первый же ответ заканчивался словами «надёжность и защищённость гейта я не подтверждаю — `done-check` вернёт 2». В финале `done-check` = **0** |
| **Дуэль Spine против LLM** | Spine **10/12 за 0.2 с**, LLM **12/12 за 300 с**; сильные стороны названы прямо (см. ниже) |

## Шесть реплик архитектора (дословно)

```
1. Мой стандарт лежит в context/standard/, репозитории перечислены в session.yaml.
   Покажи, что у меня нарушается.

2. Хочу, чтобы это проверялось в CI, и чтобы было видно, что гейт не обойти.

3. Проверь, что реестру правил можно доверять: точность и надёжность.

4. Прежде чем собирать раздатку — подготовь дуэль: мне нужны случаи с известной истиной
   и задание для LLM-участника, чтобы я прогнал его отдельно.

5. Ответы LLM-участника готовы: reports/duel-llm-1.json и reports/duel-llm-2.json.
   Посчитай дуэль, проверь готовность и собери раздатку к встрече.

6. Подтверждаю: LLM-прогон шёл в чистой копии — только cases/ и TASK.md, без доступа
   к reports/, rules.yaml и session.py. Засчитывай дуэль. И заполни pilot-canvas нашими
   данными, затем пересобери раздатку.
```

## Дуэль: Spine Core против LLM

12 случаев с известной истиной; LLM-участник запускался **в чистой копии** (только `cases/`
и `TASK.md`), два раза, в отдельных сессиях.

| Показатель | Spine Core | LLM, прогон 1 | LLM, прогон 2 |
|---|---|---|---|
| Верно решённых случаев из 12 | **10** | 12 | 12 |
| Пропущенные нарушения | 1 | 0 | 0 |
| Ложные срабатывания | 1 | 0 | 0 |
| Время | **0.2 с** | 300 с | 240 с |
| Повторяемость | идентично | 12 из 12 совпали | |

Расхождения — ровно там, где нужен смысл: **C07** (`f32` не для денег — движок считает
нарушением) и **C08** (идемпотентность только упомянута в комментарии — движок её «видит»).
Показательно, что агент сначала счёл результат LLM 12/12 **признаком утечки истины**
и потребовал подтверждения чистоты прогона — это и есть работающая честность контура.

## Что осталось незакрытым (найдено прогоном)

1. **Python 3.12 обязателен, а в SKILL.md заявлено 3.9+.** `scripts/session.py` v2 не компилируется
   на Python 3.11 (вложенные кавычки в f-string, строки 1074–1075). Прогон пришлось вести
   с `python3` = 3.12. На чистой машине с 3.9–3.11 навык упадёт с `SyntaxError`.
2. **Блок 40–55 сценария (версия стандарта и флот) не отыгран.** Агент пошёл по ветке
   «CI + дуэль» и `fleet init/bump/report` не запускал — в раздатке нет отчёта по флоту.
3. **`precision` не сертифицируется на трёх находках.** Для блокирующего режима нужен флот
   побольше или 20–30 находок на правило.
4. **Шапка `reports/check.md` — статичный текст шаблона** («warn… PASS»), который расходится
   с таблицей ниже, где есть `FAIL` и уровень `error`. Агент это заметил и вынес в отчёт.
5. **`left-pad` в `cards-product`** — не ложное срабатывание, а долг учёта исключений: override
   `ADR-041` есть в файле продукта, но не в реестре ДКА.
