# Гейт ДКА в CI

Проверка вашего стандарта переносится из «сегодня» в CI: гейт запускается на каждом
MR/PR и на `main`, и без его зелёного статуса слияние не проходит.

## Что проверяет гейт

Одна команда `arch-be gate` собирает пять независимых составляющих; провал любой — `exit 1`:

| Составляющая | Что ловит |
|---|---|
| `fitness` | нарушения правил реестра ДКА (`control check`) |
| `rule_weakened` | попытку ослабить или удалить правило реестра против `--base` |
| `delta_guard` | прямую правку защищённого спайна продукта |
| `spine_lint` | нарушения в `ARCHITECTURE-SPINE.md` |
| `trace_check` | разрывы трассировки «требование → код» (если есть `model/`) |

## Где живёт реестр правил

**Внутри репозитория продукта**: `.arch-handoff/CONSTRAINTS.yaml`. Это не удобство, а
обязательное условие — если реестр лежит вне репозитория, Spine честно отвечает
«анти-ослабление невозможно: реестр вне репозитория — сравнение недоступно»,
и попытку ослабить правила поймать нечем. Проверено: в `--explain` это отдельная
составляющая `rule_weakened`, и с внешним путём она падает в FAIL.

Владение: файл принадлежит ДКА и в Bitbucket на него настроены default reviewers.
Продукт не объявляет себе правила и не правит исключения — он их потребляет.

## Подключение

**Jenkins** — `work/ci/Jenkinsfile` в отдельной джобе ДКА (вне репозитория продукта,
чтобы продукт не мог её «починить»). Артефакты: `gate-junit.xml` (падает в UI как
failed tests с файлом и правилом), `verdict-passport.md`, `verdict.json` (пломба).

**Bitbucket** — Branch permissions → *Required builds*: статус джобы ДКА обязателен
для слияния в `main`. Плюс default reviewers на `.arch-handoff/**`.

**GitLab** — тот же `gate.sh`, артефакт `--format gitlab-codequality` в
`artifacts:reports:codequality`.

**GitHub Actions** — тот же `gate.sh`, `--format sarif` в `github/codeql-action/upload-sarif`.

## Форматы для CI

`--format junit | sarif | gitlab-codequality | markdown | json`. Машинные форматы идут
строго в stdout (артефакт), exit-код не меняется: `1` — красный, `3` — INCOMPLETE.

## Что гейт НЕ проверяет

Смотреть нужно не только на зелёное. `--explain` печатает паспорт вердикта, где это
сказано прямо:

- **правила судят по тексту**: 8 из 8 правил — про наличие/запрет слова, исполняемых
  проверок поведения — 0. Правило зеленеет и когда инвариант соблюдён, и когда о нём
  просто написали. Хрупкие правила держим в `warn`, в `block` — только проверенные selftest.
- **смысл** решений и кода механикой не проверяется (`semantic_quality` не включена).

## Brownfield

Старый долг фиксируется baseline — гейт падает только на новых нарушениях и росте
счётчика правила:

```bash
arch-be control check "$REPO" --constraints .arch-handoff/CONSTRAINTS.yaml \
  --baseline .arch-handoff/baseline.json --baseline-update   # только при неухудшении
```

## Проверка на живом контуре

`sandbox/ci-demo/` — рабочий репозиторий-демонстрация:

- ветка `main`: нарушение §5.1 (`left-pad`) → гейт красный, `fitness` FAIL;
- ветка `weaken-registry`: продукт правит реестр ДКА (понижает `block`→`warn` и убирает
  `left-pad`) → нарушение спрятано, `fitness` PASS, но `rule_weakened` FAIL → гейт
  всё равно красный.

Разбор — `reports/ci-gate.md`.
