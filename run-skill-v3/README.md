# Прогон третьей версии навыка (spine-wow-session v3)

Живой прогон **третьей версии скилла** в TUI Qwen Code 0.24.4: шесть коротких реплик
архитектора, чистая рабочая папка, проверки — механикой Spine Core (`arch-be 0.3.8`),
**Python 3.11.8** (без шимов и правок).

Сам скилл лежит в репозитории рядом: [`../skill-v3/`](../skill-v3).

## Шесть реплик архитектора (дословно)

```
1. Мой стандарт лежит в context/standard/, репозитории перечислены в session.yaml.
   Покажи, что у меня нарушается.

2. Проверь, что реестру правил можно доверять: точность и надёжность.

3. Хочу, чтобы это проверялось в CI, и чтобы было видно, что гейт не обойти.

4. Покажи стандарт как продукт: выпусти новую версию слоя и покажи, кто её ещё не применил.

5. Теперь подготовь дуэль: три участника на случаях с известной истиной.
   Наборы для LLM я прогоню сам в чистых каталогах.

6. Ответы LLM готовы в reports/duel/. Посчитай дуэль, проверь готовность
   и собери раздатку к встрече.
```

## Дуэль: три участника на 16 случаях

LLM-участники запускались в **чистых копиях** наборов `kit-llm` и `kit-combo`
(по три прогона каждый, отдельные сессии Qwen Code; каталог набора не содержал ни истины,
ни отчётов, ни `session.py`).

| Показатель | Spine Core | Чистая LLM | LLM + Spine Core | Маршрутизация (расчёт) |
|---|---|---|---|---|
| Верно решённых из 16 | **11** | 12–16 | **16** | **16** |
| Пропущенные нарушения | 3 | 0–2 | 0 | 0 |
| Ложные срабатывания | 2 | 0–2 | 0 | 0 |
| Прогонов | 2 | 3 | 3 | 1 |
| Случаев с одинаковым вердиктом во всех прогонах | **16 из 16** | **12 из 16** | 16 из 16 | — |
| Время на прогон, с | **0.2** | 240 / 53 / 300 | 300 / 180 / 420 | — |

Что это значит в переводе на язык встречи:

* **формальное и повторяемое — за движком:** 11 из 11 формальных случаев (псевдонимы типов,
  транзитивные зависимости, workspace, масштаб файла), вердикт одинаковый при каждом запуске,
  0.2 с на весь набор;
* **смысл — за моделью:** все пять смысловых случаев движок проиграл (например, `f64` в метриках
  — не деньги; идемпотентность под именем `request_id`; ключ принят и игнорируется);
* **нестабильность LLM измерима:** у чистой LLM совпали вердикты лишь в 12 случаях из 16
  между тремя прогонами — то есть в четырёх случаях ответ зависел от запуска;
* **комбинация даёт 16 из 16:** находки движка как подсказка модели закрывают и формальную,
  и смысловую части. Маршрутизация по требованиям считается по правилу, заданному до прогонов,
  и тоже даёт 16 из 16.

Агент в дуэли не участвовал и специально это оговорил: он видел случаи при подготовке,
LLM-прогоны выполнялись отдельно.

## Честные границы, названные самим агентом

1. **`pilot-canvas.md` заполнен только выводимой частью** — таблица правил с вердиктами,
   режим на старте, открытый вопрос про неизмеренную точность. Продукты, люди, владелец правил
   и критерии успеха — решения архитектора.
2. **Статичная строка в `handout/README.md`** («решает движок… повторяемо, без убеждения
   и без усталости») расходится с результатом дуэли: устойчивость и скорость подтверждены,
   а точность у движка ниже (11 против 16). Агент отказался править механизм (`cmd_pack`
   в `session.py`), но вынес расхождение в отчёт и предложил страницу-врезку с числами дуэли.
3. **`reports/duel.md` содержит истину по всем 16 случаям** — при повторной дуэли с другой
   моделью этот файл участникам показывать нельзя.
4. **`precision` не сертифицирована**: 3 находки дают нижнюю границу 0.21 < 0.9, поэтому
   в `block` разрешены только правила с подтверждённой надёжностью (2 из 6).
5. **Случаи синтетические**, 16 штук; маршрутизация — расчётная схема, а не четвёртый участник.
