## Как управлялась TUI-сессия

Экран собран из двух панелей tmux в одном окне терминала:

* **слева** — живой TUI Qwen Code в рабочей папке сессии (туда уходят промпты архитектора);
* **справа** — плашка: «что происходит», «зачем зрителю», «вердикт механики», лента событий.

Промпты отправлялись в левую панель. Конец хода агента определялся не по «тишине кадра», а по
журналу Qwen Code: журнал вырос → все вызовы инструментов получили ответ → последняя запись —
текст ассистента → кадр спокоен 40 секунд. Такой признак нужен потому, что модель подолгу думает,
не трогая ни экран, ни журнал.

Скриншоты снимались сразу после завершения хода: окно терминала поднималось, снималась его
область 1854×1048. Поэтому на каждом скриншоте одновременно видны и работа агента (слева),
и пояснение к шагу (справа).

## Оговорки

* Данные учебные: демо-стандарт платёжного ядра и три учебных Rust-репозитория. Числа прогона
  описывают репетицию, а не реальную команду.
* Режим подтверждений Qwen Code — автоматический; тем не менее агент дважды сам остановился
  и задал архитектору вопрос с вариантами (см. шаг S2).
* В учебном окружении присутствовали исходники Spine, и на шаге S2 агент прочитал
  `src/control.rs`. Для проверки навыка это не критично, но для демонстрации роли
  «архитектор-потребитель» исходники нужно убирать из рабочего окружения агента
  (подробнее — раздел 9 отчёта).
