    Правило: thiserror_for_errors (§3.2)
    Чем обходится: Ручное описание ошибки, но тип назван без суффикса Error: impl
    fmt::Display for PaymentFailure + impl std::error::Error for PaymentFailure — шаблон
    привязан к \w*Error и молчит
    Почему текстово не закрыть: Снять привязку к имени типа (for\s+\w+) нельзя: под
    правило сразу попадут законные impl fmt::Display для не-ошибочных типов — в armA это
    impl fmt::Display for PaymentStatus и для PaymentEventType. То есть мы обменяли бы
    пропуск на постоянный шум. Нужен разбор структуры (AST/линтер), а не regex
    ────────────────────────────────────────
    Правило: tech_radar_hold (§5.1)
    Чем обходится: Переименование зависимости в Cargo: lp = { package = "left-pad" } —
    deny_dependency разбирает имя ключа в [dependencies], а не package = "…"
    Почему текстово не закрыть: Внутри этого типа правила починки нет; нужен либо разбор
    поля package, либо внешний supply-chain сканер (cargo-deny) через command_succeeds в
    пилоте
    ────────────────────────────────────────
    Правило: no_box_dyn_error (§3.2)
    Чем обходится: Алиас импорта: use std::error::Error as Err; → Box<dyn Err>
    Почему текстово не закрыть: Правило текстовое (движок сам это честно называет:
    «эвристика, не AST»), алиасы не разворачивает. Нужна проверка по байткоду/rustc
