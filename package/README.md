# Пакет живого прогона навыка spine-wow-session в Qwen Code

Полный набор артефактов испытания: **что было на входе → что сделал агент → что получилось
на выходе → чем это подтверждается**. Прогон выполнен 24.09.2026 на локальной машине,
в TUI Qwen Code, от лица архитектора домена «Платежи».

```
ВХОД                                          ВЫХОД
стандарт (Confluence-экспорт)   ──┐
контекст сессии (session.yaml)  ──┤           work/requirements.md      7 требований (A=4, B=2, C=1)
три репозитория архитектора     ──┼──► Qwen ──► work/CONSTRAINTS.corp.yaml 6 правил со std_ref
промпты архитектора (8 шагов)   ──┤     Code    reports/                    8 отчётов Spine Core
навык spine-wow-session         ──┘    + arch-be sandbox/                    флот, лазейки, эффективный файл
                                              handout/ + zip              10 файлов раздаточного пакета
```

## Доказательства «из журнала, а не из текста модели»

| Инструмент агента | Вызовов |
|---|---|
| `run_shell_command` | 31 |
| из них `session.py` (оркестратор навыка) | 12: `preflight`×3, `check`×3, `selftest`×2, `fleet init/bump/report`, `bypass`, `pack` |
| `read_file` | 26 |
| `write_file` / `edit` | 8 / 3 |
| `skill` | 1 (явная активация навыка) |
| `ask_user_question` | 1 (остановка на решение архитектора) |

Все отчёты созданы механикой Spine Core (`arch-be control check / control report`), а не текстом
модели: находки несут `std_ref` («Стандарт платёжного ядра v2 §3.2») и позицию `src/error.rs:50`.

## Что подтверждено, а что нет

**Подтверждено:** навык устанавливается и активируется в свежем Qwen Code; агент следует его
процедурам; Spine Core работает при вызове из Qwen Code; находки прослеживаются до пунктов
стандарта; навык останавливается на решение человека, не ослабляет правила ради зелёного
результата и сам называет незакрытые пункты.

**Не проверялось:** промышленная готовность контура ДКА (прогон учебный: демо-стандарт и учебные
репозитории) и полный 90-минутный сценарий встречи — живые блоки (шаг P3 архитектора и эксперимент
с дрейфом P5) не отыгрывались.

## Найденные дефекты (подробно — в отчёте, раздел 9)

1. Демо-правило `new-rules.yaml` заняло `id: C-PAY-005`, который уже был у `observability_standard`.
2. Шаблон `anyhow::|Box<dyn` пересекается с правилом `no_box_dyn_error` — двойные находки.
3. Реестр ДКА (`work/`, 2026.1) и песочница флота (`sandbox/`, 2026.2) разошлись версиями.
4. `pilot-canvas.md` остался шаблоном.
5. Эксперимент с дрейфом (P5) не поставлен.
6. `effective-corp.yaml` не попадает в раздаточный пакет.
7. Крючок встречи держится на §3.2: правило §2.1 на учебных репозиториях даёт ноль находок.
8. Агент читал исходники Spine (`src/control.rs`), хотя для роли потребителя достаточно бинаря.
